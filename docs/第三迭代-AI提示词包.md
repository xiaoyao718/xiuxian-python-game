# 第三迭代 AI 提示词包（回合制答题战斗 + 剧情 + 仙侠视觉）

用法：每条提示词配"万能前缀"使用；一条一个目标，跑完验收再发下一条；默认决策点=计划书 ★ 值（D6 已用"夜巡二人组"）。

## 0. 万能前缀（每次必带）

```
项目：修仙学 Python（纯静态 HTML/CSS/JS 网页游戏，零构建、无外部依赖），仓库根目录即你的工作目录。
动手前先通读：docs/第三迭代计划书-v0.1-回合制战斗+剧情+视觉.md（要实现的计划书）、index.html、
css/style.css、js/data.js、js/game.js、js/pet.js、js/fx.js、js/sound.js、js/runner.js、
scripts/validate-data.js、README.md。
现状基线：v1.1 已上线（6 关主线 15 题 + 巩固 8 题 + 灵宠分阶 72 题；场景粒子/山河路线图/灵宠灵器行囊/
立绘槽位/错题本/以练促养/存档 v2/Pages 自动发布）。
铁律：
1. js/data.js 只做纯新增，禁止改写任何既有剧情文案、题目与关卡结构；
2. 不引入外部库/新 CDN 依赖；美术一律内联简笔 SVG / 像素矩阵 / Canvas 原生；
   素材接入遵循"0.5 素材接入规范"（免费工具产出轻产物；禁止 Spine/Lottie/Three.js 等运行时库）；
3. 所有动效尊重 prefers-reduced-motion（直接降级），375px 无横向溢出，移动端自动降量；
4. window.App 接口保持兼容，既有功能零回归（错题本/试炼/C型题/灵宠/行囊/Boss diff/Skulpt/键盘/抽屉/音效）；
5. 每批验收门：node --check 全部 js → node scripts/validate-data.js 全 PASS →
   （涉及战斗）node scripts/test-battle.js 全绿 → 无头浏览器或手动全流程冒烟（控制台零异常）；
6. 所有代码题/大招题的预期输出必须用本机 python 3.14 实测后再定答案；
7. 清理自己产生的临时文件；完成后汇报：改动文件清单 + 实现要点 + 自查结果。
```

## 0.5 素材接入规范（免费工具链 · 新增，随万能前缀使用）

```
项目美术素材生产与接入规范（全部免费工具离线产出，游戏内只放轻产物）：
1. 角色像素小人：用 LibreSprite / Piskel（免费）绘制 → 产物二选一：
   a) 导出 PNG 雪碧图 + 帧信息 → assets/sprites/<id>.png，引擎 drawImage 按帧播放；
   b) 转成 GAME_DATA.sprites 像素矩阵（16×16、pal 调色板索引、frames idle×2/attack×2/hit/defeat）。
   渲染统一 image-rendering:pixelated，放大 4-6 倍；调色板从墨黑/纸白/金/朱 + 角色专属色中取。
2. 立绘：Krita（免费）产出 512×512 透明底 PNG → assets/portraits/<说话人>.png，
   对接既有立绘槽（.portrait-slot 读该路径自动生效）。
3. 场景/概念背景：AI 生图（即梦/可灵/通义万相，免费额度）产出 16:9 低饱和水墨 PNG/WebP
   （单张 ≤300KB，画面禁止出现任何文字），存 assets/scenes/ 并挂到对应 html[data-scene] 的 .env-art；
   或 Inkscape 矢量 SVG。
4. 特效：优先程序化（Canvas/CSS 直接写，零素材）；仅当需要"电影感"时用序列帧——
   AE/剪映导出 PNG 序列放 assets/fx/<效果名>/frame-###.png（单帧 ≤60KB、全序列 ≤2MB），
   用 CSS steps() 或 Canvas 帧播放；禁止引入 Spine/Lottie/Three.js 等任何运行时库。
5. 3D/体素（Blender/MagicaVoxel 免费）：只离线产出 PNG 设定图/封面渲染图当网页素材，游戏本体不加载 3D。
6. 音效：免费素材站（爱给网等）下载小体积 ogg/mp3 放 assets/audio/（单条 ≤300KB），
   或继续用 WebAudio 合成。
7. 你（AI）在需要新素材时：先输出《素材规格单》= 尺寸/调色板/帧清单/存储路径/命名/风格描述，
   不要自己假装生成图片；用户用上述免费工具按规格单产出后放入 assets/，你再写加载与播放代码，
   并把新文件加入 validate-data.js 的存在性校验。
8. 体积红线：单次迭代新增素材总量 ≤3MB；首屏增量克制；reduced-motion 下序列帧不播放；
   移动端优先程序化特效。
```

### 0.6.2 人设卡模板（新增角色/伙伴时用，喂 AI 产出）

```
请为角色 X 输出一份人设卡（与上述档案同构）：
1) 基本信息：姓名/身份/年龄/所属势力/与林慕关系；
2) 外观描写（60 字内，可被像素与立绘直接转译）：身形/衣着配色/标志物/专属纹样；
3) 性格与口头禅：3 个性格标签 + 1 句口头禅 + 1 个"露怯/柔软"的破绽点；
4) 专属色 hue 与单字 glyph（朱印用）；
5) 像素造型要点：16×16 内可辨认的关键特征（如林韬的鹤、章管事的山羊胡）；
6) 台词声音：说话节奏/用词习惯/对林慕的称呼；
7) 剧情位置：在哪些章出现、与伏笔 F1-F7 的关联、战败后态度变体（rivalWin）；
8) 禁忌：不得出现与该角色设定冲突的行为（如周显不会当面道谢）。
```

### 0.6.3 像素小人视觉提示词（喂给 LibreSprite/Piskel 绘制者或 AI）

```
按角色档案为 X 设计 16×16 像素小人：
- 画布 16×16，调色板 ≤12 色，从"墨黑/纸白/金/朱 + 角色专属色"体系取；
- 三视图先定轮廓（正/侧 45°/背面剪影可辨），再画 6 帧：
  idle×2（呼吸浮动差）、attack×2（前冲/挥击）、hit×1（受击后仰）、defeat×1（倒地或垂头）；
- 关键特征必须在 16×16 内可读（例：林韬=锦袍高领+扬下巴；章管事=山羊胡+官帽）；
- 表情映射：idle 倨傲/坚毅、hit 惊怒、defeat 嘴硬不认或狼狈；
- 底色透明；输出：字母画布示意 + 调色板表 + 最终二维索引数组（pal 索引）或雪碧图。
```
