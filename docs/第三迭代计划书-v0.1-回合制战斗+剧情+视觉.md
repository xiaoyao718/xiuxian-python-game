## 0. 三层目标

1. 玩法层：把“答对=释放技能”升级为完整回合制 RPG 答题战斗（我方答 Python 题放技能，敌方出找茬题施压，大招必须手写代码）。
2. 剧情层：战斗叙事化（每场反派对决都有情绪与关系推进）+ 主线伏笔网（仙典来历 / 秘境真相 / 周显心结 / 小师妹线），伏笔只埋不收，谜底留第二卷。
3. 视听层：宏大仙侠界面 + 像素小人角色 + 中国修仙仙侠特效；传统文化元素（太极、八卦、五行、符箓、诗词）分阶段注入，太极先行试点。

## 2. 玩法范围（沿用用户 v0 拍板项，摘要）

- 战斗循环：我方回合=4 技能槽选一→弹选择题→答对命中/答错落空+吃反击；敌方回合=直接攻击(50%)或出找茬题(50%，答对免伤+敌方 taunt，答错反噬并记错题本)；循环至一方 HP 归零。
- 插入位置：静室试炼通关后、破境之前（lv1–lv5 各一场反派对决）；终章 Boss 保留“写代码渡劫”，v0 不套回合。
- 敌方：lv1 夜巡二人组（组合单位，呼应第一章“窗外两个笑你的人”）/ lv2 林韬（灵兽苑）/ lv3 章管事 / lv4 周显 / lv5 妖狼王；技能主题=对应章节语法。
- 四技能槽：=已学语法主题，技能名借灵宠风味（灵雀报信·print 等）；命中后从同主题选择题池抽“本场未出现”的题补位；普通技能只用选择题，大招才上代码。
- 大招：敌方 HP≤30% 进入“灵力见底”，普通技能锁定，只能写代码（Skulpt 运行→norm 比对；离线降级“PyCharm 运行后粘贴输出”，与 Boss 判定同款）；答错给 hint 可重试但敌方攻击一次。
- 血量/灵力：由通关章节数+境界推导，v0 不新增成长存档字段。
- 失败处理：败北=再战（状态/题序全重置，无惩罚）或撤退回章节入口。
- 伙伴结构：data 预留 companions 结构与 addFighter 钩子，v0 不实装剧情伙伴；敌方保持单体。
- 灵宠援护：开战自动带当前最高阶灵宠：本场首次答错免伤（灵光护体+援护文案）。

## 3. 剧情扩充模块（新增，分层落地）

### L1 战斗叙事化（随 P1 战斗一起实现，纯文本+极小存档）

- 每场反派对决配齐三件套：战前登场卡挑衅台词（呼应本章剧情）→ 战中 taunt 库（3-5 句随机）→ 战后服软/退场台词。
- 关系推进：战后在存档记 rival 标记（如 e_lintao_night:'defeated'），该角色后续出场台词自动切换（林韬从“废物”变嘴硬、周显从“刻薄”变忌惮）。
- 台词走 GAME_DATA 数据表（enemy.intro/taunt/win + rival 变体字段），改词不动代码。

### L2 主线伏笔网（P2 落地，全部“追加式”插入，不改写既有任何句子）

## 4. 视觉升级方向（新增，分阶段）

### R1 宏大仙侠界面（P1 战斗场景起逐步铺开）

- 战斗对峙构图：舞台中央双方对峙、背景沿用 data-scene 天色并加“天地级”远景（云海之上远山、宗门剪影、光柱）；战前登场卡全屏化（巨字+朱印+烟墨入场）。
- 主线界面：主舞台内容区微扩（≤1080px），对话框半透明浮于宏大场景；章节封面 Hero 段增强。
- 铁律：前景文字可读性优先、低饱和、reduced-motion 全降级、375px 不破版。

### R2 像素小人（P1 简版先行）

- 定位：重水墨世界 × 像素众生（水墨背景 + 像素角色），风格统一且有记忆点。
- 清单（v0.1 首批 6 个）：林慕、林韬、周显、章管事、妖狼王、夜巡二人组（组合单位）；白鹤为灵兽苑彩蛋可选；小师妹仅建档待用。
- 规格：16×16 逻辑像素 × 调色板索引矩阵（墨黑/纸白/金/朱 + 角色专属 hue）；帧：idle×2、attack×2、hit×1、defeat×1；放大 4-6 倍渲染，image-rendering:pixelated；reduced-motion 用静止帧。
- 存放：像素矩阵放 js/sprites.js（独立文件便于 Node 校验），渲染器独立函数，可单测（尺寸/调色板索引合法性）。
- 灵宠 v0 沿用现有简笔 SVG（可后续像素化）。

## 5. 数据与代码分层（沿用铁律：data.js 只纯新增）

```js
// data.js：battles + 台词（敌方找茬题池按 v0.2 以 tag:"trap" 或人工索引表指定）
GAME_DATA.battles = [
  { id, levelId, enemy:{ id,name,glyph,hue,hp,atk,intro,taunt[],win,rivalWin? },
    ult:{ lead, expected, hint } }
];
// js/sprites.js：SPRITES = { linmu: { pal:[...], size:16, frames:{...} }, ... }
// js/balance.js：BATTLE_BALANCE（敌 HP/攻、我方成长、大招阈值、找茬概率）
```

- 敌方找茬题源 = 同章主题 petQuests 中带 tag:"trap" 的题（或人工索引表）；普通题源 = questions/quizExtra/petQuests（不新建题库）。
- 新增文件：js/battle.js（回合引擎+战斗 UI）、js/battle-core.js（纯逻辑，Node 可测）、js/sprites.js（像素数据与渲染器）、js/balance.js（战斗数值）、scripts/test-battle.js（Node assert，零依赖）。
- game.js 只在静室试炼通关回调插 App.startBattle()，胜利复用 finishLevel；失败不写档。
- 存档：v2 增加可选字段 rival:{}（默认空，迁移零成本）。
- validate-data.js 新增：battles 五场齐全/指向存在关卡/大招题非空/台词数组非空；sprites 尺寸 16×16、pal 索引不越界、帧数符合规格；找茬题池（带 trap 标记）每章 ≥8、普通题 ≥10。

## 6. 测试方案（用户点名 Code Testing）

scripts/test-battle.js（Node 内置 assert）：回合状态机推进与终态只触发一次；伤害结算各分支；四技能槽换题与同场不重复；大招 30% 阈值/锁定/命中未命中/反复失败扣血；援护挡首次答错；失败重试全重置且进度不污染；边界（HP 同时归零、恰好 30%、无宠阵容）；sprites 渲染数据合法性。

执行门：node --check 全部 js → test-battle 全绿 → validate-data 全 PASS（含新增）→ 无头浏览器全流程冒烟（375px + reduced-motion + 控制台零异常）。
